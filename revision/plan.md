# 改訂スケジュール（2026年9月〜2027年5月）

## ゴール

Go Conference 2027 のプロポーザル募集が始まる前に、本書を「現代の Go で通読でき、公開できる状態」にすることをゴールにします。

2026年は、募集期間が 5/15〜6/15、選考結果の通知が7月中旬、開催が 9/11 でした（[プロポーザル募集開始のお知らせ](https://gocon.jp/2026/news/proposal-recruitment/)）。2027年も同じ時期だと仮定し、**2027年4月末を完成の締め切り**にしています。5月前半は、公開した本を見ながらプロポーザルを書く期間として空けておきます。募集要項が発表されたら日付を見直します。

## CFP 時点での「完成」の定義

83件のタスクすべてを7か月で片付けるのは現実的ではありません。そこで、CFP 時点での完成を次の状態と決め、それ以外は「CFP後」に回します。

- 誤った情報・非推奨 API を主題にした説明が本文に残っていない
- 構文解析 → 型解析 → パッケージの読み込み → go/analysis の流れが通しで読める
- WIP の章は目次から外すか、「今後の予定」として明示してある
- サンプルがすべて最新の Go で動き、CI で確かめられている
- Web で公開されている

フロー解析（SSA）と、事例章の大部分はこの範囲に入れていません。フロー解析は重い章で、事例章は旧版の書き直しになるため、どちらも CFP後の2周目で扱う方が本全体として良くなると判断しました。

各タスクがどのマイルストーンに入るかは `tasks.csv` の「マイルストーン」列に書いてあります。

## 伴走のしかた

隔週（毎月1日と15日の朝）に編集チェックインを行います。その時点までのコミットと、スプレッドシートのステータスを見て、次のことを短く返します。

- 前回からの進み具合（マイルストーンに対して予定どおりか）
- 新しく書かれた原稿への編集コメント（構成・説明の順序・技術的な正確さ・読者がつまずきそうな箇所。原稿は書き換えず、指摘だけする）
- 次の2週間でやると良いこと
- Go や x/tools のリリースで本書に影響する変更があれば、その知らせ
